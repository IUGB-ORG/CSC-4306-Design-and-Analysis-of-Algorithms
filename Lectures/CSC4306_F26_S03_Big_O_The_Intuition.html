From Session 2
We counted comparisons and timed both searches. Linear search multiplies when n doubles; binary search adds one. Today we give these behaviours names, so that we can talk about them without a table of numbers every time.

1 · Why a Notation Is Needed 15 min

Suppose careful counting gives a function the running time

T(n) = 3n2 + 17n + 42

This is more precision than anyone can use. The 3 depends on how fast your processor multiplies; the 17 on how your compiler arranged the loop; the 42 on the cost of calling a function. Change the machine and all three numbers change — but something about the expression does not change. Let us find out what.

At n = 1 the constant 42 is most of the cost — and nobody cares, because everything is fast at n = 1. By n = 10,000 the other two terms together account for less than one part in a thousand. In the region where performance is actually a problem, the expression is its leading term.

2 · The Three Moves 20 min

Move 1 — Drop the constants
5n, n and 0.01n all become n. A constant factor is what you buy with a faster processor. This course is about the factors you cannot buy.
Move 2 — Keep the dominant term
In a sum, the fastest-growing term wins eventually and by an ever-widening margin. n² + 1000n becomes n², even though 1000n is larger until n = 1000.
Move 3 — Think large n
The description is about behaviour eventually. It says nothing about n = 5, and it is not supposed to.
What survives
A statement about shape that outlives the machine, the compiler, the language and the decade. We write it as O(n²), pronounced “big oh of n squared”.
T(n) = 3n2 + 17n + 42   is   O(n2)

The last row surprises people. n100 is astronomically larger than 2n for every n below about 1000 — but exponentials overtake every polynomial eventually, and “eventually” is what Move 3 tells us to look at.

What the moves are not They are not a claim that constants do not matter in practice. A program twice as fast is twice as fast, and your users will notice. The claim is narrower and stronger: constants cannot change which algorithm wins in the end, and they are not a property of the algorithm at all.

3 · Six Shapes, Read Off the Code 30 min

In practice you will rarely calculate T(n) and simplify it. You will read the growth class off the structure of the code. Six shapes cover nearly everything you meet this semester.

PYConstant
def first_element(A):
    return A[0]
O(1) The work does not depend on len(A). Double the input and nothing changes. Indexing, arithmetic and dictionary lookup all live here.
PYLinear
def total(A):
    s = 0
    for v in A:
        s += v
    return s
O(n) One pass, constant work per element. Double the input, double the time. Any single loop over the data lands here — and so does linear search.
PYLogarithmic
def count_halvings(n):
    steps = 0
    while n > 1:
        n = n // 2       # divided, not decremented
        steps += 1
    return steps
O(log n) Double the input and the cost rises by exactly one. This is binary search. The operator is what decides: n -= 1 would make this linear, n //= 2 makes it logarithmic.
PYQuadratic
def count_pairs(A):
    pairs = 0
    for i in range(len(A)):
        for j in range(len(A)):
            if A[i] + A[j] == 0:
                pairs += 1
    return pairs
O(n²) A loop inside a loop, each over the whole input: n × n. Double the input and the time goes up fourfold. This is the first class that genuinely fails on real data — around a million elements it becomes unusable.
PYLinearithmic
def biggest_gap(A):
    B = sorted(A)                 # sorting costs O(n log n)
    best = 0
    for i in range(len(B) - 1):   # one extra pass costs O(n)
        best = max(best, B[i + 1] - B[i])
    return best
O(n log n) Sorting dominates the scan, so O(n log n) + O(n) collapses to O(n log n) by Move 2. This is the cost of every good sorting algorithm and, in practice, the ceiling of what is comfortable on large data.
PYExponential
def subsets(A):
    if not A:
        return [[]]
    rest = subsets(A[1:])
    return rest + [[A[0]] + s for s in rest]
O(2ⁿ) Every extra element doubles the answer and therefore the time. At n = 50 there are about 1015 subsets: a machine producing a billion per second needs roughly thirteen days. At n = 100 it needs longer than the universe has existed.

4 · Why Shape Beats Hardware 15 min

The natural objection: if my computer is fast enough, does the growth class really matter? Suppose you run an O(n²) program on a machine ten times faster than mine, while I run an O(n) program on an old laptop. Your cost is n²/10; mine is 100n.

Hardware buys a crossover point, not a victory. Your faster machine wins for every input below n = 1000. From there on mine wins, and the gap widens without limit. Buying a machine a hundred times faster moves the crossing to n = 10,000 — it does not change who wins in the end.
The central claim of this course
Hardware improves by constant factors. Algorithms improve by changing the shape. Constant factors are bought; shapes are earned. Over the last fifty years, the speed-ups obtained from better algorithms have exceeded those from faster processors on many of the problems that matter most.
A caveat worth stating out loud None of this says the O(n²) program is the wrong choice. If you know n will never exceed 200, the quadratic program may be simpler, shorter, and faster in practice. Knowing which regime you are in is part of engineering judgement; Big-O tells you what happens when you are wrong about n.
Session 3 Takeaway
Drop the constants, keep the dominant term, look at large n — what remains is the shape of the cost, and that is what Big-O records. Six shapes cover most of computing, and you can usually read the right one straight off the loop structure. Hardware shifts the crossover point; only a better shape changes the outcome.

In-Class Exercises (work in pairs)

  1. Simplify to a single growth class: 4n + 9; n²/2 − 3n; 2n log n + 5000n; 7; n + 2ⁿ; n² + n log n + 1000.
  2. A program takes 3 seconds on input of size 1000 and 12 seconds on size 2000. Which class is it in? Predict the time for size 4000 and for size 16,000.
  3. Give the growth class of each, with a one-line reason: (a) finding the largest element of a list; (b) checking whether a list is sorted; (c) checking whether any two elements are equal, using two nested loops; (d) printing all the ways to arrange n people in a queue.
  4. Your colleague says “my algorithm is O(n²), but the constant is tiny, so it beats the O(n log n) one.” Under what circumstances is this true? Under what circumstances is it a dangerous thing to say?
  5. Sketch, without a computer, roughly where n log n and n²/4 cross.
