Learning Objectives

  • Build a recursion tree from a recurrence in four steps.
  • Compute the cost of one level and count the number of levels.
  • Decide which of the three regimes applies: root-dominated, balanced, or leaf-dominated.
  • Solve T(n) = 2T(n/2) + n, T(n) = 2T(n/2) + 1 and T(n) = 3T(n/2) + n by tree.
  • Say what the Master Theorem is for, and why we are not using it.
From Session 9
Unrolling works beautifully when there is one recursive call. With two, the expression branches at every substitution and the algebra becomes unmanageable — as Exercise 4 was designed to show you. A picture handles branching far better than a line of algebra does.

1 · The Method 12 min

Draw the root and label it with the non-recursive work the top-level call does: f(n). Not T(n) — just the glue.
Give it a children, each a subproblem of size n/b, and label each with the glue it does: f(n/b). Repeat downward.
Cost each level: multiply the number of nodes at that level by the work per node.
Count the levels, then add the level totals.
Why this is an argument and not merely a drawing Every node of the tree corresponds to exactly one invocation of the function, and its label is exactly the work that invocation does outside its own recursive calls. So the sum of all the labels is the total work — no invocation is counted twice and none is missed. Grouping that sum by level is just a convenient order of addition.

2 · The Central Case: T(n) = 2T(n/2) + n 18 min

Level by level. Level 0 is one problem of size n, doing n units of glue. Level 1 is two problems of size n/2, doing n/2 each — total n again. Level 2 is four problems of size n/4, doing n/4 each — total n. The width of the bars shrinks but the number of bars grows at exactly the same rate, so every level costs the same.
cost of one level = n  ·  number of levels = log₂ n + 1
T(n) = n · (log₂ n + 1) = Θ(n log n)

Where does log₂n + 1 come from? The subproblem size is n, n/2, n/4, …, and the recursion stops when it reaches 1. That happens after log₂n halvings — exactly the count we derived for binary search in Session 9, and exactly Chantal's sixteen questions from Session 1. The same quantity keeps reappearing because it is the same phenomenon.

3 · When the Levels Are Not Equal 25 min

3.1 T(n) = 2T(n/2) + 1 — the leaves win

Same split, but each node does only constant work. Level d holds 2d nodes costing 1 each, so level d costs 2d. The level costs are 1, 2, 4, 8, … — they double as we descend.

1 + 2 + 4 + … + n = 2n − 1 = Θ(n)

This is the doubling series from Session 5, and there we noted that such a series is dominated by its last term. The bottom level alone holds n nodes and accounts for half the total. So the answer is simply the number of leaves.

Why binary tree traversal is Θ(n)
Visiting every node of a balanced binary tree with n nodes has exactly this shape: two recursive calls, constant work at each node. Students often guess Θ(n log n) because “there are log n levels”. There are — but the levels are not equal, and the last one alone contains half the tree.

3.2 T(n) = 2T(n/2) + n² — the root wins

Level 0 costs n². Level 1 is two problems of size n/2, each doing (n/2)² = n²/4, so the level costs n²/2. Level 2 costs n²/4. The level costs halve as we descend:

n² + n²/2 + n²/4 + … < 2n² = Θ(n²)

The halving series from Session 5 is dominated by its first term. The root does more work than everything below it put together, so the answer is just f(n).

3.3 T(n) = 3T(n/2) + n — the leaves win again, less obviously

Three subproblems, each of half the size. Level d holds 3d nodes of size n/2d, so it costs 3d · n/2d = n(3/2)d. The level costs are n, 1.5n, 2.25n, … — growing by a factor of 3/2, so again the bottom dominates. The number of leaves is 3log₂n = nlog₂3.

T(n) = Θ(nlog₂3) ≈ Θ(n1.585)

This is the shape of Karatsuba's fast multiplication algorithm: three half-sized multiplications instead of the four that schoolbook multiplication needs. Reducing a from 4 to 3 moved the exponent from 2 to 1.585 — which is why that trick was worth a paper.

One question settles all of them
Going down one level, does the total work grow, stay the same, or shrink?
Grows → the bottom dominates; the answer is the number of leaves, alogbn = nlogba.
Stays → multiply one level's cost by the number of levels: f(n) · log n.
Shrinks → the root dominates; the answer is f(n).
Memorise this question, not the five rows above it. The rows are consequences.
On the Master Theorem There is a general theorem covering T(n) = aT(n/b) + f(n), which compares f(n) against nlogba and produces exactly the three regimes above. It is stated in Appendix A at the end of this lecture series, together with the awkward cases it handles and the gap where even it does not apply. We do not use it in the main line of the course. A rule that returns an answer without a picture is a poor way to learn where the answer comes from, and every recurrence you will meet this term yields to the question in the box above. Once you can draw the tree in your sleep, read the appendix and the theorem will look obvious — which is the right order.

4 · A Tree That Is Not Balanced 15 min

Not every recursion splits evenly. Consider T(n) = T(n/3) + T(2n/3) + n — the shape of quicksort when the pivot always lands one third of the way along, which we will meet on 3 November.

Each level still costs n, because the two children's sizes add up to the parent's: n/3 + 2n/3 = n. That holds all the way down. But the branches now bottom out at different depths: the leftmost path shrinks by a factor of 3 each step and ends after log₃n levels, while the rightmost shrinks by only 3/2 and survives for log3/2n levels — about 1.7 times longer.

n · log₃n  ≤  T(n)  ≤  n · log3/2n
both bounds are Θ(n log n), since logarithm bases differ only by a constant
Why this matters more than it looks
A wildly unbalanced-looking split — one third against two thirds — gives the same complexity class as a perfect halving. Only the constant changes. This is the reason quicksort works in practice despite almost never splitting evenly, and it is worth carrying into November.
Session 10 Takeaway
Draw the tree, cost one level, count the levels, and ask whether the level costs grow, hold, or shrink going down. Grow → count the leaves. Hold → one level times the number of levels. Shrink → the root. Three regimes, one question, no theorem required. The recurrences of this course are now solved problems, and on Friday we finally meet the algorithm that T(n) = 2T(n/2) + n was written for.

In-Class Exercises (15 min — work in pairs)

  1. Draw the tree and give Θ for each: (a) T(n) = 4T(n/2) + n; (b) T(n) = 2T(n/4) + n; (c) T(n) = T(n/2) + n; (d) T(n) = 9T(n/3) + n².
  2. For each of the four above, first predict the regime (grow / hold / shrink) before computing, then check yourself.
  3. Two students disagree about T(n) = 2T(n/2) + n. One says Θ(n log n); the other says the tree has n leaves so it must be Θ(n). Locate the error in the second argument precisely.
  4. For T(n) = aT(n/2) + n, at what value of a does the answer stop being Θ(n log n)? What happens just below that value, and just above?
  5. Draw the tree for T(n) = T(n/5) + T(4n/5) + n and bound the number of levels on the shortest and longest paths.
